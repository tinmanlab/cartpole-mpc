# N-pendulum CartPole: definition, implementation and solvability boundaries

## Definition, not a claim of arbitrary-N control

The new experiment uses **one cart force and N serial unactuated revolute joints**. It is not N independent/parallel pendulums, N separate agents, or N actuators. We call link count `n_poles` and prediction length `horizon` to avoid the previous overloaded N notation.

The grouped state is `[cart_x, q_1..q_N, cart_v, w_1..w_N]`, with dimension `2(N+1)`. Every q_i is relative to its parent; absolute link angle is the cumulative sum of q_1..q_i, wrapped for reporting. Upright means all absolute link angles zero. For N=1 this grouped order differs from the legacy `[x,v,theta,omega]`; the permutation is tested explicitly. All angles/rates use radians/radians per second internally.

The default model fixes each pole at 1 m full length and 0.1 kg, with a 1 kg cart, ideal horizontal force +/-10 N and world rail +/-2.4 m. Thus increasing N changes total height/mass as well as state dimension. Do not call this a pure solver-dimension benchmark. Different per-link masses/lengths are definable; a constant-total-mass/length campaign would be a separate experiment.

## Reuse and model authority

DeepMind's existing `dm_control/suite/cartpole.py::_make_model` already constructs a serial chain and exposes two-pole/three-or-more-pole tasks. The inspected file revision is `87e046bfeab1d6c1ffb40f9ee2a7459a38778c74` (Apache-2.0). We reuse that nested-body construction pattern, not a newly derived N-body dynamics equation, its reward, or its policy benchmark.

`scripts/build_chain_assets.py` extends the repository's explicit-inertia canonical MJCF. N=1 with default parameters is **byte-identical** to `assets/cartpole.xml`. Each child is attached at its parent's tip. Mass, COM at half the full length, rod transverse inertia `m*length^2/12`, visual geometry and named endpoint sites remain consistent. There is only one cart motor; no hinge actuation is added.

The generator admits integer N from 1 to 32 as a resource bound, not a mathematical limit. Native MuJoCo compilation/dimension/parentage tests cover every integer N=1..32 and custom three-link physical parameters. Packaged browser models/profiles cover 1..8. Greater N is not automatically a validated control configuration.

The new adapter calls the **same pinned official MuJoCo WASM 3.7.0** for stepping and geometry. It adds a dimension-aware state mapping; it does not implement physics. All geometry is non-colliding, as in the original ideal-force experiment. Self-collision, joints with electrical motor dynamics, flexible links and contact impacts are not represented.

## What was and was not generalizable

The existing four-state engine hardcodes state indexing, H=[position, first angle], 2x2 measurement inversion, four-state iLQR/MHE/residual networks and single-pole rendering. Its existing Riccati terminal helper intentionally accepts only 4x4 models. Merely increasing a pole count would make those paths invalid.

The new N view reuses the generic upstream `quadprog` transcription and matrix utilities, but does not claim all legacy controllers/observers generalize. The original implemented modes were:

- nominal local linear MPC, full Riccati terminal cost, input and world-rail constraints;
- saturated LQR using the same offline nominal cost/design;
- explicit truth/oracle feedback, or a stationary-gain linear Kalman observer receiving cart position plus **every relative joint encoder**, not true velocities.

Riccati and stationary Kalman gains are generated by `scipy.linalg.solve_discrete_are`; dynamics derivatives use native MuJoCo `mjd_transitionFD` and four-substep composition at upright. Stored profiles are tied to exact asset hashes. The stationary observer is not a generalized EKF or online covariance calibration. Its process/measurement covariances and supplied encoder noise are declared simulation assumptions.

The original two measurements are not automatically theoretically insufficient: the nominal PBH tests also find local observability with cart position and first hinge alone for these model instances. That does NOT validate a noisy high-order two-sensor estimator. The closed-loop results here use all joint encoders, and do not claim equivalence to that reduced sensor set.

## Numerical/physical verification

1. Generator identity, dimensions, body parentage, single force input, positive inertias, relative-to-absolute forward kinematics and invalid-parameter rejection.
2. Actual WASM versus native MuJoCo: 50 prescribed control steps for each N=1..8 using exactly the same MJCF. Maximum recorded component discrepancy is approximately 4.51e-13 across the checked runs.
3. Actual WASM finite-difference linearization versus native `mjd_transitionFD`/substep composition, with unchanged 1e-7 element tolerance. N=1 also matches the legacy backend after the explicit state permutation.
4. Short integration refinement: native Euler at 1/4/16 substeps versus a smaller-step RK4 reference, separately from cross-runtime identity. This is a finite convergence probe, not an exact-time or global simulation guarantee.
5. Nominal PBH controllability/observability singular-value tests, reconstructed Riccati residual and closed-loop/error-system eigenvalues. These are local numerical evidence at the stated model/units, not arbitrary-N nonlinear reachability proofs.
6. Independent native sparse OSQP solves of frozen nominal QPs. Its normalized stationarity gate is explicitly different from the browser absolute KKT gate; do not compare unlike tolerances as if identical.

`evidence/chain_reference.json` records each result, including unsuccessful OSQP solves. N=1..3 frozen QP probes were admitted; N=4..6 hit the declared iteration budget. An iteration limit or a solver message is not a theorem of infeasibility. These timings are host-specific offline calculations, not admitted hardware deadlines.

## Frozen closed-loop screen — baseline at 32462cb

`tests/fixtures/chain_validation.json` is fixed before the first run. For each N=1..8 it requests three initial/target/push cases, two controllers and two observation modes: **96 configurations** total. Each admitted run lasts up to 600 steps = 12 s. Initial angles are specified in absolute coordinates then converted to relative hinges. No weights/horizon/limits were retuned against the results.

Completion and task success are separate. Completion requires no numeric rejection and no rail or 35-degree absolute-link-angle envelope failure. Task success additionally requires the last 100 samples to keep every link within 0.02 rad of upright and cart position within 0.1 m of the target. Declared gates apply to this experiment only.

| Links | State dimension | Completed / 12 | Task achieved / 12 | Main observed boundary |
|---:|---:|---:|---:|---|
| 1 | 4 | 12 | 12 | all three selected cases |
| 2 | 6 | 8 | 8 | large-angle case rejected/falls |
| 3 | 8 | 5 | 5 | some noisy/pushed or larger initial cases fail |
| 4 | 10 | 2 | 2 | gentle LQR with oracle and encoders succeeds; QP numerical gate rejects |
| 5 | 12 | 0 | 0 | selected starts exceed useful controller domain; QP rejects |
| 6 | 14 | 0 | 0 | selected starts/noise and numerical conditioning remain unresolved |
| 7 | 16 | not executed | not executed | Riccati numerical admission fails before control |
| 8 | 18 | not executed | not executed | Riccati numerical admission fails before control |

N=7/8 have 12 configuration rejections each, not 12 hidden physical rollouts. Their Riccati residuals exceed the predeclared 1e-9 criterion, despite computed local stable eigenvalues. Condition numbers grow from about 2.05e2 (N=1) to 2.11e6 (N=4), 7.63e8 (N=6), and 2.91e11 (N=8). This records a numerical design boundary, not physical impossibility.

For N=4 the successful LQR trials themselves disprove an inference that 'four poles cannot be controlled' from the failed QP attempt. The local controller and estimator assumptions, conditioning, input bounds and recovery domain all matter.

## Separate micro-local diagnostic

After examining the frozen results, `scripts/probe_chain_local.mjs` uses a nonzero 1e-7 rad initial absolute perturbation, zero target and 40 s duration for N=4,5,6. This is explicitly a post-baseline diagnostic, not an untouched test or a useful robust-control claim.

Oracle LQR completes all three. With the declared 2e-4 encoder noise and stationary filter, N=4 completes while N=5 and 6 fail. Thus N=5/6 are demonstrably not simply 'unsolvable'; the tested noiseless local region exists, but the practical noisy-estimation and force-limited region is much narrower. Vanishingly small oracle trials must not be substituted for the selected task results above.

## Baseline next-step rationale (subsequent implementation below)

Investigate numerical scaling/pre-stabilized or sparse OCP formulations on the same frozen problem before calling all QP rejection physical infeasibility. Preserve the input/world-rail semantics and independently compare recovered inputs/costs. Then characterize estimator/noise sensitivity and actual recovery regions; nonlinear MPC/swing-up is a separate specification, not a label added to this LTI experiment. Do not hide these gaps by relaxing residual checks, shrinking every initial perturbation, adding actuator authority, or copying true state into a sensor-only trial.

### Exact matched-state QP comparison

The final reference test also evaluates the browser quadprog and native OSQP on identical state/reference/cost/constraints, separately from the three closed-loop initial conditions. Both admit N=1..3, with maximum first-input discrepancy 4.20e-8 N and maximum relative cost discrepancy 2.55e-8. In the specific N=4 fixed-state probe quadprog admits a solution while OSQP reaches its iteration limit. For N=5/6 quadprog rejects and OSQP reaches its limit. A missing jointly admitted solution is reported as unavailable parity, not zero error or physical impossibility.

## Professionalization: separate numerical solvability from output-feedback robustness

The following extension builds on the **recorded** direct-input results above. The original frozen manifest, model profiles, physical limits and cost parameters are unchanged. These known cases now serve as development/regression evidence, not newly untouched final-test data. The old direct-MPC and LQR modes remain available and are still the defaults.

### A. Exact pre-stabilized MPC coordinates

`mpc_pre` writes the same prediction/control sequence in coordinates

    u_k = -K e_k + v_k
    e_(k+1) = (A-BK)e_k + B v_k

where e is the reference-relative state and K is the existing nominal Riccati gain. For fixed initial e_0, this is a bijective lower-triangular change of decision variables. It is NOT a separately added physical LQR loop, extra actuator, changed objective or relaxed input authority.

The local adapter assembles all original state/input quadratic terms and the full terminal P using stable transition powers. Bounds apply to **u**, not v: `-10 <= -K e_k + v_k <= 10`. The cart rail remains in world coordinates. The same quadprog Goldfarb–Idnani optimizer is called; no new numerical optimizer is implemented.

With an exact Riccati terminal P, the identity `J=e_0' P e_0 + sum(v_k' (R+B'PB) v_k)` explains the excellent conditioning. The implementation nevertheless retains the full original cost rather than dropping finite-precision Riccati residual terms. In the fixed nominal tests, the direct condensed Hessian condition number rises from about 615 (one link) to 1.73e9 (four) and 1.88e13 (six), while the transformed Hessian remains close to condition 1. This result is tied to this P/Q/R design; arbitrary terminal penalties need not have that property.

Verification includes arbitrary-vector cost/coordinate identity, transformed original physical constraints, original-unit trajectory defects, and independent NumPy assembly plus OSQP solutions. Input-active and rail-active cases are included; inactive v=0 solutions alone are not sufficient tests. Both numerical solvers agree on first input and full original cost. The independently assembled N=1..6 inactive reference solves use 25 OSQP iterations; this does not imply every constrained state solves in 25 iterations.

Acceptance still uses 1e-7 absolute KKT and 1e-8 primal thresholds in the solved coordinate problem, plus 1e-8 physical input/rail and dynamics reconstruction checks. An original state/input adjoint calculation separately checks normalized stationarity at 1e-7 and reports its absolute value. KKT residuals are coordinate-dependent: the transformed number is not silently equated to the old untransformed absolute residual. Original direct-QP tests and thresholds are not weakened. An unadmitted plan is never applied.

### B. Actual N-dimensional nonlinear EKF

The new explicit `ekf` option predicts through the same MuJoCo WASM map, recomputes the state Jacobian each step, uses the all-encoder measurement matrix, and performs Joseph-form covariance correction with the existing matrix solver. It has dimension checks, finite-state checks, relative-angle residual handling, prefit innovation/NIS and prediction-only handling of a missing measurement.

It receives only noisy cart/joint measurements and commanded force. Truth is not passed into the observer, and the unknown external push is not supplied as known prediction input. The test class accepts a missing sample, but the fixed N-chain screen still uses the previously declared nonmissing independent encoder noise; missing-data robustness is a separate experiment.

Q_e/R_e and the initial nominal posterior are held at the same declared values as the existing stationary Kalman design. This isolates nonlinear prediction and covariance evolution; it is not claimed to be optimal noise calibration. A NumPy reference checks mean, Joseph covariance, innovation covariance and NIS on N=1,3,6 cases. Correct equations do not prove field-calibrated covariance, nonlinear global observability, InEKF reproduction or superiority over stationary KF.

### C. Matched outcomes: improvements and retained failures

The stable-coordinate comparison uses the same three cases and the same oracle/encoder modes as the direct-MPC subset (six requests per N). N=4 gentle balancing, which direct MPC rejected numerically, now completes with both oracle and stationary-KF feedback. With the new EKF it also completes. Larger initial/reference cases remain rejected or fail; N=5/6 do not achieve the frozen task grid, and N=7/8 remain design-rejected before execution.

Each count here is task achievement, not just a low mean error. The three-case EKF column cannot be summed or compared as if it had the six oracle/KF trials. In the three-link tracking_push scenario it reaches a rejection earlier (31 steps) than the stationary filter (51 steps), before the scheduled external push at step 200. That failure concerns the initial/reference transient, not a measured response to a push that never occurred. This is a counterexample to treating a newer observer label as automatic improvement.

### D. Output feedback, separation and noise-to-force gain

Stable controller poles and stable observer poles are insufficient measures of usable robustness. In the ideal linear unsaturated system, let e=x-x_hat, F=A-BK and E=(I-LH)A. The joint deterministic matrix is block triangular:

    [x+]   [F   BK] [x]   [ 0] measurement_noise
    [e+] = [0    E] [e] + [-L]

The unsaturated command is `u=[-K,K][x;e]`. `scripts/diagnose_chain_output_feedback.py` solves the joint discrete Lyapunov equation using SciPy and independently checks the command variance by impulse-energy summation. The instantaneous measurement-to-command gain is K L; the full steady-state variance includes the estimator and plant dynamics rather than treating measurement noise as direct state error.

At the declared independent sensor standard deviations (2e-4 m for cart position and 2e-4 rad for each joint), the ideal stationary **unsaturated linear** command standard deviations are approximately:

| Links | sigma_u [N] | Actual declared force range |
|---:|---:|---:|
| 1 | 0.0274 | +/-10 N |
| 2 | 0.1183 | +/-10 N |
| 3 | 0.3741 | +/-10 N |
| 4 | 1.3159 | +/-10 N |
| 5 | 5.3129 | +/-10 N |
| 6 | 22.8562 | +/-10 N |

The six-link linear analysis predicts a command distribution that is inconsistent with remaining unsaturated. This flags a serious sensor/controller/actuator operating-margin problem even though all separate nominal poles are stable. It is not the actual variance of the clipped nonlinear MPC and not a calibrated probability of falling. Simply changing a QP solver, substituting EKF, or increasing Q_e/R_e without evidence does not close this gap.

A separate one-control-sample (20 ms) input-delay spectrum test checks both an unmodeled delay and an observer that knows the queued applied command. One-step equations are independently reconstructed before reporting the spectra. Several higher-order cases cross unit spectral radius. Knowing the applied-input history is not equivalent to redesigning the controller for delay. This is a linear diagnostic, not implemented asynchronous sensing or hardware-delay compensation.

### E. Local admissible region, not a nonlinear safety certificate

The diagnostic also checks `P-F'PF` numerically and constructs an ellipsoid `e'Pe <= c` contained within declared LQR force, absolute-link-angle and symmetric rail-margin inequalities. For a scalar inequality `|a'e|<=b`, the sufficient bound is `c <= b^2/(a'P^-1 a)`. A positive Lyapunov decrease establishes a nominal linear, constant-reference, disturbance-free argument inside that set.

This set is NOT added as an MPC terminal constraint, not validated under nonlinear dynamics/noise, and not promoted as a safe hardware region. It is a starting analytical object for local-region verification. The earlier 1e-7-rad oracle experiments are also only micro-local diagnostics, not replacements for practical initial-condition/noise tests.

### F. What the existing toolkit can solve, and what it still lacks

The available MPC/LQR/KF machinery solves the declared local one-/two-/three-link cases and a gentle four-link case once the numerical formulation is repaired. It does not yet solve arbitrary reference transitions, large-angle recovery/swing-up, or the declared noisy five-/six-link task grid. The repository has not made all its four-state UKF/MHE/PPO/NMPC paths N-dimensional; only the specifically tested EKF extension is added here. acados remains an optional separate research path, not the browser's hidden fallback.

The next engineering requirements are based on diagnosed failure mechanisms:

1. **Feasible target/trajectory and domain of attraction:** distinguish reference feasibility, initial-state recovery and task tracking; evaluate a reference/trajectory governor or native nonlinear OCP when the task demands leaving the local region. This is not permission to weaken the physical rail or relabel nominal feasibility as nonlinear safety.
2. **Calibration and output-feedback bandwidth:** identify sensor noise, bias, quantization, process/model error and their time dependence; design Q_e/R_e and control bandwidth jointly against force/slew authority. Inspect innovation whiteness/coverage, noise-to-control gain and held-out behavior. A Kalman filter can be mathematically correct yet poorly matched to that requirement.
3. **Delay and actuator authority:** acquisition/application timestamps, queued-command prediction, known input delay, slew/voltage/thermal limits and target-processor timing. These are absent from the ideal N-chain plant and cannot be supplied by a faster solver alone.
4. **Uncertainty-aware constraints and recovery:** only after specifying the uncertainty model, consider tightening/tube/chance/robust-MPC constructions, verified terminal/recovery sets and a platform-specific protective stop. No generic finite-grid or gaussian-band statement is a hardware safety certificate.
5. **High-order numerical design:** balanced/scaled Riccati and sparse/pre-stabilized QP/OCP representations with independent checks, especially before admitting N=7/8. Keep solver status, residuals and physical task outcomes distinct.

These are conditional design needs, not an instruction to install every method or a new control framework at once. Frozen weights, physical limits, assets and sensor authority remain unchanged in this change.

### G. Feasibility witness is separate from optimality and model validity

A final diagnostic uses SciPy's existing HiGHS linear-programming interface with zero objective and the **same** native sparse linear dynamics, initial condition, input bounds and cart rail. It does not change the MPC controller, substitute an LP policy, or apply its witness to the plant. Bounds are explicitly supplied for signed state variables; default nonnegative LP variables are not used.

At the 18 oracle initial conditions for admitted N=1..6, 16 have a directly verified feasible witness. All three N=4 conditions and the gentle/tracking starts for N=5/6 have witnesses, despite some QP attempts failing numerical admission. The N=5/6 boundary cases are reported infeasible by HiGHS for the specified finite linear problem. That solver status is not an exact arithmetic certificate of arbitrary nonlinear/hardware impossibility.

A witness is checked in original coordinates for dynamics and physical-bound residuals (at most about 2.22e-12 in this run). It proves existence of a feasible point for the stated linear constraints, not optimality, stability, recovery or task success. Since the original problem has no hard absolute-angle or terminal-region constraint, the zero-cost LP can return very large predicted pole angles. This is NOT a claim that the optimal quadratic MPC chooses those same angles. It demonstrates why finite-horizon rail/input feasibility must not be equated with validity of the local linear prediction or successful physical balancing.

The purpose is diagnostic separation: numerical failure, lack of feasible nominal trajectory, exit from model-validity region, and noisy closed-loop failure require different corrections. An angle trust region, terminal/recovery set, feasible reference generator or native nonlinear OCP should be selected according to the actual task; none is silently added or tuned merely to turn the frozen grid green.
